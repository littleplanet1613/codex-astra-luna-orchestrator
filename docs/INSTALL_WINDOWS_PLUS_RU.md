# Установка на Windows для ChatGPT Plus

Эта инструкция рассчитана на профиль **Plus**.

## Что получится после установки

Codex будет использовать:

- GPT-5.6 Luna `max` как главный root/orchestrator;
- GPT-5.6 Luna `medium` для explorer, worker, tester и researcher;
- GPT-6 Astra `low` как независимый reviewer;
- до 4 concurrent subagents по умолчанию.

## Вариант 1 — установка в конкретный проект

1. Клонируйте этот репозиторий:

```powershell
git clone https://github.com/littleplanet1613/codex-astra-luna-orchestrator.git
cd codex-astra-luna-orchestrator
```

2. Запустите Windows-установщик:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

Если используется PowerShell 7:

```powershell
pwsh -File .\setup.ps1
```

3. Когда установщик попросит путь к целевому проекту, укажите папку проекта, где должен работать Codex.

4. Выберите:

```text
2) Plus
```

5. По умолчанию установщик предложит три части:

- `.codex` — конфигурация Codex и роли агентов;
- `.agents` — skill `astra-orchestrator`;
- `AGENTS.md` — инструкции по оркестрации для проекта.

6. Если какой-то файл уже существует, внимательно смотрите список файлов, которые будут заменены. Существующие настройки MCP, providers, permissions и другие ручные настройки нельзя перетирать вслепую.

7. Запускайте Codex из целевого проекта. Project-scoped `.codex` загружается только для trusted projects.

## Вариант 2 — глобальная установка

Если хотите использовать роли во всех проектах, можно установить их в пользовательские папки.

Агенты:

```text
~/.codex/agents/
```

Skill:

```text
~/.agents/skills/astra-orchestrator/
```

Настройки из `profiles/plus/codex/config.toml` нужно **объединить** с существующим:

```text
~/.codex/config.toml
```

Не заменяйте глобальный `config.toml` целиком, если там уже есть MCP-серверы, провайдеры, permissions или другие настройки.

## Проверка после установки

После запуска Codex в проекте можно явно вызвать:

```text
$astra-orchestrator
```

И дать тестовую задачу, например:

```text
$astra-orchestrator

Изучи текущую структуру проекта без изменений.
Пусть explorer найдёт основные точки входа и тесты.
Ничего не редактируй.
```

Ожидаемый результат: root должен реально создать subagent `explorer`, а не просто написать, что «мысленно» разделил работу.

## Что не надо делать

- Не запускать полный оркестратор для каждой мелкой правки.
- Не повышать все роли до Astra без причины — это быстро расходует лимиты.
- Не включать 6–8 параллельных агентов, пока не доказано, что задачи независимы.
- Не перезаписывать существующие конфиги Codex вслепую.

## Рекомендуемый режим для Plus

Простая правка → root-only.

Сложная задача на несколько файлов → orchestrator + explorer/worker/tester.

Нужна внешняя документация → researcher.

Нужна независимая финальная проверка → reviewer Astra.

Установку этого репозитория рекомендуется выполнять одновременно с `open-steps`, чтобы не было конфликтов между глобальными `AGENTS.md`, skills и hooks.
