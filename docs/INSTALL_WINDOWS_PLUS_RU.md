# Установка на Windows для ChatGPT Plus

Эта инструкция рассчитана на профиль **Plus**.

## Что получится после установки

Codex будет использовать:

- GPT-6.2 Sol `high` как главный root/orchestrator;
- GPT-6 Luna `medium` для explorer и worker, `high` для tester;
- GPT-6.2 Sol `medium` для researcher;
- GPT-6.2 Astra `medium` как независимый reviewer;
- GPT-6.1 Terra `medium` как read-only visual-inspector;
- до 4 concurrent subagents по умолчанию.

## Вариант 1 — установка в конкретный проект

1. Клонируйте этот репозиторий:

```powershell
git clone https://github.com/littleplanet1613/codex-astra-luna-orchestrator.git
cd codex-astra-luna-orchestrator
```

2. Запустите Windows-установщик:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

Если используется PowerShell 7:

```powershell
pwsh -File .\setup.ps1
```

3. Когда установщик попросит путь к целевому проекту, укажите папку проекта, где должен работать Codex.

4. Выберите:

```text
2) Plus
```

5. По умолчанию установщик предложит три части:

- `.codex` — конфигурация Codex и роли агентов;
- `.agents` — skill `astra-orchestrator`;
- `AGENTS.md` — инструкции по оркестрации для проекта.

6. Если какой-то файл уже существует, внимательно смотрите список файлов, которые будут заменены. Существующие настройки MCP, providers, permissions и другие ручные настройки нельзя перетирать вслепую.

7. Запускайте Codex из целевого проекта. Project-scoped `.codex` загружается только для trusted projects.

## Вариант 2 — глобальная установка

Если хотите использовать роли во всех проектах, можно установить их в пользовательские папки.

Агенты:

```text
~/.codex/agents/
```

Skill:

```text
~/.agents/skills/astra-orchestrator/
```

Настройки из `profiles/plus/codex/config.toml` нужно **объединить** с существующим:

```text
~/.codex/config.toml
```

Не заменяйте глобальный `config.toml` целиком, если там уже есть MCP-серверы, провайдеры, permissions или другие настройки.

## Проверка после установки

После запуска Codex в проекте можно явно вызвать:

```text
$astra-orchestrator
```

И дать тестовую задачу, например:

```text
$astra-orchestrator

Изучи текущую структуру проекта без изменений.
Пусть explorer найдёт основные точки входа и тесты.
Ничего не редактируй.
```

Ожидаемый результат: root должен реально создать subagent `explorer`, а не просто написать, что «мысленно» разделил работу.

## Что не надо делать

- Не запускать полный оркестратор для каждой мелкой правки.
- Не повышать все роли до Astra без причины — это быстро расходует лимиты.
- Не включать 6–8 параллельных агентов, пока не доказано, что задачи независимы.
- Не перезаписывать существующие конфиги Codex вслепую.

## Рекомендуемый режим для Plus

Простая правка → root-only.

Сложная задача на несколько файлов → orchestrator + explorer/worker/tester.

Нужна внешняя документация → researcher.

Нужна независимая финальная проверка → reviewer Astra.

Установку этого репозитория рекомендуется выполнять одновременно с `open-steps`, чтобы не было конфликтов между глобальными `AGENTS.md`, skills и hooks.
## Проверка GPT-6.2 перед установкой в рабочий проект

1. В PowerShell 7 проверьте `codex --version` и `codex login status`.
   Нужен CLI 0.166.0 или новее и вход под аккаунтом ChatGPT Plus. В новом
   сеансе сначала проверьте Sol 6.2 и Astra 6.2 через `/model` и выполните
   по одному короткому запросу на каждой модели.
2. В клоне проверяемой ветки запустите `python -m unittest discover -s tests -p "test_*.py"`
   (Python 3.11+) и `pwsh -NoProfile -File .\tests\test_setup.ps1`.
   Дымовой тест использует временный каталог и проверяет отказ от перезаписи.
3. Запустите `pwsh -NoProfile -File .\setup.ps1`, укажите отдельный временный
   Git-репозиторий и выберите **2 (Plus)**. Если AutoCAD MCP или другие MCP с
   правом записи доступны из глобальных настроек, выключите их на время
   испытания через настройки Codex. Проверьте, что инструменты записи недоступны.
4. Из тестового репозитория откройте новый сеанс Codex и подтвердите доверие
   только к этому каталогу. Проверьте выбранную модель по умолчанию и запустите
   каждую из шести именных ролей по очереди на безвредной задаче. В журнале
   запуска сверяйте фактические модель и роль, включая Luna и Terra. Проверьте
   запись Worker и Tester только в тестовый файл. Для строгого контроля
   write-доступа запустите отдельный сеанс `codex --sandbox read-only --ask-for-approval never`
   без MCP с правом записи и проверьте, что запись тестового файла блокируется.
5. Установите Open Steps по инструкции его форка и запустите новый сеанс.
   Отдельными запросами проверьте все семь навыков и один обычный запрос без
   активации. На локальном фиктивном сценарии с якобы зелёным PR проверьте,
   что навыки сообщают о готовности без выполнения merge или деплоя.
6. Перед переносом в рабочий проект снимите копии существующих `.codex`, `.agents`
   и `AGENTS.md`. Сопоставьте проектные MCP и правила с результатом стендовой
   установки. При откате закройте Codex и восстановите эти компоненты из копий.
   Для компонентов, которых до установки не было, уберите добавленные файлы.
